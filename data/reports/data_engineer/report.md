# Отчёт Data Engineer: Очистка датасета Fake Job Postings

## Контекст и бизнес-задача
В рамках разработки системы бинарной классификации мошеннических вакансий был подготовлен пайплайн очистки сырых данных. Цель модели — минимизировать ручную модерацию и защитить соискателей от скама. Приоритетная метрика — F1-score / Recall по классу 1 (мошеннические вакансии).

## Исходные данные
- **Источник:** `data/raw/fake_job_postings.csv`
- **Целевая переменная:** `fraudulent` (оставлена без изменений, балансировка классов не применялась во избежание утечек данных на этапе валидации).

## Реализованные шаги очистки
1. **Удаление мусора:** Идентификатор `job_id` удален. Колонки, содержащие более 70% пропусков, исключены из датасета.
2. **Обработка числовых признаков:** Пропуски заполнены медианой. Применен клиппинг по 1-му и 99-му перцентилям для защиты от выбросов.
3. **Обработка категориальных признаков:** 
   - Пропуски заполнены модой.
   - Признаки с количеством уникальных значений менее 20 закодированы с помощью One-Hot Encoding (`drop_first=True`).
   - Признаки с высокой кардинальностью (20 и более уникальных значений) закодированы через Frequency Encoding (частота встречаемости категории).
4. **Текстовые признаки:** Колонки `title`, `location`, `department`, `salary_range`, `company_profile`, `description`, `requirements`, `benefits` оставлены в исходном виде (as_is). Их векторизация и фиче-инжиниринг переданы на сторону Data Scientist'а.
