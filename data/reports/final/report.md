# Финальный отчёт: Классификация мошеннических вакансий

**Бизнес-задача:** Разработка модели бинарной классификации для выявления мошеннических вакансий на HR-площадке. Цель — снижение ручной модерации и защита пользователей от скама. Приоритетная метрика — F1-score / Recall по классу 1 (мошенничество) при контроле Precision.

## Executive summary
Команда завершила разработку end-to-end ML-пайплайна для автоматического выявления мошеннических вакансий. Проведена полная очистка сырых данных, выполнен разведочный анализ, подтвердивший сильный дисбаланс классов, и сгенерированы новые признаки на основе текстов и метаданных. Подготовлена инфраструктура для обучения, тюнинга и честной валидации моделей (Logistic Regression, Random Forest, Gradient Boosting), однако точные метрики финальной модели пока не получены и ожидают завершения прогона пайплайна.

## Ключевые находки
* Выявлен сильный дисбаланс целевой переменной (`fraudulent`), что потребовало внедрения взвешивания классов (`class_weight='balanced'`) на этапе обучения моделей.
* Анализ показал, что индикаторы доверия (наличие логотипа `has_company_logo` и вопросов `has_questions`), а также доля пропусков в текстовых полях (например, `company_profile`) обладают высокой предсказательной силой для выявления скама.
* Определенные категории вакансий выступают как маркеры риска: административные функции, требования образования уровня старшей школы или сертификатов, позиции начального уровня и стажировки, а также частичная/временная занятость.
* Финальная модель, её гиперпараметры и итоговое значение метрики test f1 на данный момент не получены (в отчете DS зафиксированы плейсхолдеры), результаты будут доступны после полного прогона пайплайна обучения.

## Что сделал Data Engineer
Был подготовлен пайплайн очистки сырых данных (`data/raw/fake_job_postings.csv`):
* **Удаление мусора:** Исключен идентификатор `job_id` и колонки, в которых более 70% пропусков.
* **Числовые признаки:** Пропуски заполнены медианой. Для защиты от выбросов применен клиппинг по 1-му и 99-му перцентилям.
* **Категориальные признаки:** Пропуски заполнены модой. Признаки с кардинальностью менее 20 уникальных значений закодированы через One-Hot Encoding (`drop_first=True`). Признаки с 20 и более уникальными значениями закодированы через Frequency Encoding.
* **Текстовые признаки:** Поля `title`, `location`, `department`, `salary_range`, `company_profile`, `description`, `requirements`, `benefits` оставлены "как есть" для дальнейшей обработки.
* **Итог:** Сформирован очищенный датасет `cleaned.csv`, целевая переменная `fraudulent` оставлена без изменений для избежания утечек.

## Что нашёл Data Analyst
Проведен разведочный анализ данных (EDA) на базе очищенного датасета:
* **Дисбаланс классов:** Рассчитан Imbalance Ratio, подтвержден сильный дисбаланс легитимных и мошеннических вакансий.
* **Корреляционный анализ:** Выявлен Топ-10 признаков по модулю корреляции с таргетом. Построена тепловая карта для Топ-15 признаков для проверки на мультиколлинеарность.
* **Анализ бинарных признаков:** Рассчитана вероятность мошенничества для значений 0 и 1. Выделен Топ-5 признаков с наибольшей разницей в вероятности фрода.
* **Анализ текстов (метаданные):** Выявлены различия в длине текстов (Word Count) между классами (особенно для `description`). Проанализирована доля пропусков (NaN Rate) — проверялась гипотеза о том, что мошенники чаще оставляют пустыми определенные поля (например, `company_profile`).

## Что обучил Data Scientist
Построен end-to-end пайплайн для обучения и оценки моделей:
* **Сплит данных:** Использован Stratified split на train, val и test для честной offline-оценки и защиты от утечек.
* **Feature Engineering:** Созданы признаки доверия (`has_company_logo`, `has_questions`), мета-признаки текстов (длина, пропуски, наличие URL/email/телефонов/денежных терминов), флаги рискованных категорий (административная работа, начальный уровень, частичная занятость) и эвристики по заголовкам (доля капса, сеньорность). Итоговые фичи сохранены в `features.csv`.
* **Модели:** В качестве бейзлайнов заложены `LogisticRegression`, `RandomForestClassifier` и `GradientBoostingClassifier`.
* **Тюнинг и пороги:** Настроен `RandomizedSearchCV` (3 фолда, метрика F1). Порог классификации (threshold) подбирается динамически по PR-кривой с приоритетом на удержание Precision >= 0.5.
* **Результаты:** На данный момент обучение не завершилось (в отчете присутствуют плейсхолдеры). Конкретное название лучшей модели, её параметры и метрики (F1, Precision, Recall, ROC AUC, PR AUC) не получены.
* **Контроль качества:** В пайплайн заложена логика сравнения новой модели с предыдущей лучшей по метрике `test_metrics.f1` для предотвращения деградации продакшена.

## Что дальше
Для дальнейшего улучшения качества детекции мошенничества планируется:
* Подключить градиентный бустинг (`LightGBM` / `XGBoost`) с параметром `scale_pos_weight` для лучшей работы с дисбалансом и повышения PR-AUC.
* Внедрить NLP-методы: добавить TF-IDF векторизацию по полям `title`, `company_profile` и `description`.
* Применить Out-of-fold Target Encoding или Frequency Encoding для сложных категориальных признаков.
* Провести Error Analysis (анализ ошибок) по ложноположительным и ложноотрицательным срабатываниям модели.
* Согласовать с бизнесом жесткий SLA по метрике Precision и зафиксировать под него подбор порога (threshold).
